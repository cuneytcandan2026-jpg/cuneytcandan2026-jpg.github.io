- [x] **Phase 7 — Pricing polish + "not sure which package".** Added a compact 3-question mini-tool below the pricing cards — deliberately not a clone of pricing.html's full "Help Me Choose" (separate `pricing.js`/`pricing-data.js`, not loaded on the homepage): same scoring facts and tie-break rule (ties default to Professional, per pricing.md's stated sales goal), but instead of a duplicate result panel it highlights the matching card already on screen (green ring via `.is-recommended`, tied to each card's new `data-package` attribute) and states the match in text for `aria-live` announcement. Fixed by adding the missing `--laara-space-5: 1.25rem` token rather than patching each call site. Verified the scoring logic against 3 scenarios (essential/professional/growth all reachable and correct), confirmed real Tab-key keyboard focus shows a visible ring (an initial programmatic-focus test gave a false negative), and checked both breakpoints.
- [x] **Phase 8 — How It Works animated progress.** Found the existing `.process-connector` CSS was already half-built but completely unused — no matching element existed anywhere in `index.html`. Wired it up: a horizontal line through the icon centres that draws left-to-right (`scaleX` fill) once the section enters view, with each icon flipping from ink to green in sequence via per-icon `transition-delay` (150/450/750ms) timed to look like "the line reaching each step" — no continuous scroll-position tracking needed, it reuses the same one-time shared IntersectionObserver every other `.reveal` on the page already uses. Deliberately did *not* attempt a literal connecting line on mobile: with items stacked in normal flow, each step's height varies with its paragraph length, so there's no reliable way to calculate icon-centre-to-icon-centre spacing in pure CSS (unlike desktop, where CSS Grid keeps all three icons on the same row regardless of text length) — would need JS measuring live layout for a decorative line, not worth it. Mobile keeps the plain vertical stack with its existing staggered fade-up. "7–10 days" stays plain static text, no counting animation, so the factual-animation rule was never at risk here. Verified the stagger is genuinely progressive (icon 1 starts turning green before icon 2, confirmed by sampling mid-transition) and that the end state settles with all three icons green and the line fully drawn, at both breakpoints.
